# [실습 1] 공동책임모델 워크시트 작성해보기 — 양식과 작성 예시

> 1장 [실습] 1번에서 사용하는 워크시트입니다. 클라우드 콘솔 하나에는 계정, 권한, 키, 네트워크 노출, 패치, 암호화, 백업, 로그처럼 여러 관리 항목이 딸려 있습니다. 그래서 **콘솔을 가로(열)로, 관리 항목을 세로(행)로** 놓고, 콘솔마다 한 열씩 채워 나갑니다. 콘솔이 늘어나면 오른쪽으로 열을 추가하면 됩니다.

---

## 작성 방법

1. **콘솔 목록 만들기**: 회사가 관리자 화면(콘솔)을 가지고 있는 클라우드 서비스를 모두 적습니다. IaaS(AWS, Azure 등)뿐 아니라 SaaS(Microsoft 365, Google Workspace, 그룹웨어, 협업 도구)도 각각 하나의 콘솔입니다.
2. **기본 정보와 접근·노출 현황 채우기**: 서비스 유형(IaaS·PaaS·SaaS), 소유 부서, 운영 담당자를 적습니다. 이어서 최고 권한 계정과 관리자 MFA, 발급된 장기 접근 키·API Key, 네트워크 노출(인터넷에 열린 포트와 공개 주소)을 사실 그대로 적습니다.
3. **책임 구분 표시**: 다섯 가지 관리 항목(패치, 접근 통제, 암호화, 백업, 로그)마다 책임이 누구에게 있는지 표시합니다.
   - **공급자**: 클라우드 공급자가 책임지고, 우리는 확인만 하면 되는 영역
   - **우리**: 우리 회사가 직접 설정하고 운영해야 하는 영역
   - **공동**: 공급자가 기능을 제공하고, 켜고 설정하는 것은 우리 몫인 영역
4. **담당자와 현재 상태 적기**: "우리" 또는 "공동"으로 표시한 항목에는 반드시 담당자 이름과 현재 상태를 적습니다.
5. **빈칸 찾기**: "우리" 또는 "공동"인데 담당자가 **미지정**인 칸을 찾아 표시합니다. 이 칸이 설정 오류로 외부에 노출되기 가장 쉬운 지점입니다.

## 예시에서 읽어야 할 것

**같은 항목도 서비스 유형에 따라 책임이 달라집니다.** 패치 관리는 IaaS인 AWS에서는 게스트 OS부터 우리 몫이지만, SaaS인 Microsoft 365에서는 공급자가 책임집니다. 1-2에서 본 IaaS·PaaS·SaaS의 책임 범위 차이가 워크시트에서 그대로 드러납니다.

**어떤 서비스든 접근 통제는 항상 "우리" 몫입니다.** 공급자가 아무리 많은 것을 맡아도, 누구에게 어떤 권한을 줄지는 우리가 결정합니다. 예시에서 관리자 권한 남발, 퇴사자 계정, 누구나 링크가 모두 이 행에서 나왔습니다.

**키와 네트워크 노출은 따로 세어 봐야 보입니다.** 1-3과 1-4에서 본 것처럼 공격은 유출된 키 하나, 인터넷에 열린 포트 하나에서 시작됩니다. 그래서 이 두 행은 책임 구분을 따지기 전에 현황부터 숫자로 적습니다. 예시에서는 1년 넘게 바꾸지 않은 액세스 키, 설정 파일에 저장된 키, 전 세계에 열린 SSH 포트가 이 묶음에서 드러났습니다.

**"공동"이 가장 위험합니다.** 공급자가 기능을 제공하니 "알아서 되겠지"라고 생각하기 쉽지만, 실제로는 우리가 켜고 설정해야 동작합니다. 예시에서 백업은 두 콘솔 모두 담당자가 **미지정**이었습니다. Microsoft 365처럼 SaaS라도, 사용자의 실수 삭제나 랜섬웨어로 지워진 데이터를 되살리는 것은 공급자의 기본 책임 범위가 아닌 경우가 많습니다.

**미지정 칸이 곧 다음 사고 지점입니다.** 체크포인트에서 말한 것처럼, 담당자가 없는 항목은 아무도 설정을 확인하지 않으므로 기본값이나 잘못된 설정이 그대로 남습니다. 종합 행의 "담당자 미지정 항목"을 먼저 채우는 것이 이 워크시트의 목적입니다.

> **작성 팁**
> - 콘솔이 5개를 넘으면 표가 너무 넓어지므로, 엑셀이나 스프레드시트에 같은 구조로 옮겨 쓰는 것을 권장합니다.
> - "현재 상태"는 "적용/미적용"보다 **구체적인 사실**(예: "개발자 2명에게 관리자 권한")을 적어야 조치로 이어집니다.
> - 책임 구분이 헷갈리면 공급자의 공식 공동책임모델 문서를 확인합니다. 같은 공급자라도 서비스마다 책임 범위가 다릅니다(예: AWS의 EC2와 RDS).
> - 4~6장에서 다루는 AI 서비스(AI SaaS, 모델 API, Agent 플랫폼)도 같은 워크시트에 열을 추가해 관리할 수 있습니다. 이때는 "Prompt·응답 데이터 보존"과 "모델 학습 활용 여부" 행을 추가합니다(6-2 참고).
